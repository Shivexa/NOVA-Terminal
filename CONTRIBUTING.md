# Contributing to NOVA Terminal

Thank you for your interest in contributing to NOVA Terminal by Shivexa.

We welcome suggestions, bug reports, and improvements that help make NOVA Terminal better.

## How to Contribute

### 1. Report Bugs
- Describe the issue clearly.
- Include steps to reproduce it.
- Mention your operating system, Python version, and NOVA Terminal version.
- Remove API keys, passwords, and other sensitive information from logs.

### 2. Suggest Features
- Explain the proposed feature.
- Describe the problem it solves.
- Include examples where possible.

### 3. Submit Code Changes
1. Fork the repository if external contributions are enabled.
2. Create a separate branch for your changes.
3. Make focused, well-documented changes.
4. Test your changes before submitting them.
5. Submit a pull request describing your changes.

## Coding Guidelines

- Write readable and maintainable code.
- Follow consistent Python coding conventions.
- Avoid unnecessary dependencies.
- Do not commit API keys, credentials, `.env` files, or other secrets.
- Update documentation when behavior or commands change.
- Add tests when practical.

## Pull Request Guidelines

A pull request should include:
- A clear summary of the changes.
- The reason for the changes.
- Relevant testing details.
- Any documentation updates required.

## Security Issues

Do not report security vulnerabilities in public issues. Follow the instructions in [SECURITY.md](SECURITY.md) to report them responsibly.

## License and Contributions

NOVA Terminal is distributed under its applicable proprietary licensing terms. Submitting a contribution does not automatically grant permission to redistribute the project or its source code. Contribution terms may require separate written agreement.

## Code of Conduct

Be respectful, constructive, and professional when interacting with other contributors.
