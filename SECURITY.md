# Security Policy

## NOVA Terminal — Shivexa

Shivexa takes the security of NOVA Terminal seriously. We appreciate responsible reports that help us protect users and improve the software.

## Supported Versions

Security updates are prioritized for the latest supported release of NOVA Terminal.

| Version | Security Support |
|---|---|
| Latest release | Supported |
| Older releases | Not guaranteed |

## Reporting a Vulnerability

If you discover a potential security vulnerability in NOVA Terminal, please report it privately through an official Shivexa communication channel.

Please include:

- A clear description of the vulnerability.
- Steps to reproduce the issue.
- The potential impact.
- Relevant logs or screenshots, with sensitive information removed.

Please do not publicly disclose the vulnerability until Shivexa has had a reasonable opportunity to investigate and address it.

## Security Best Practices

Users should:

- Never share their Gemini API keys or other secret credentials publicly.
- Never commit API keys, passwords, tokens, or `.env` files to GitHub.
- Keep Python, Node.js, NOVA Terminal, and its dependencies updated.
- Review commands before executing them, especially commands suggested by AI.
- Download NOVA Terminal only from trusted distribution sources.

## AI Mode and API Keys

NOVA Terminal's AI Mode may use a Gemini API key supplied by the user.

Users should keep their API keys private and follow Google's applicable API security guidelines. Any API key storage or handling in NOVA Terminal should be implemented securely.

## Scope

This policy covers security vulnerabilities in NOVA Terminal and its officially maintained components. Third-party services and dependencies may have their own security reporting procedures.

## Responsible Disclosure

We welcome responsible security research conducted lawfully and without compromising other users' data, systems, or privacy.

Thank you for helping make NOVA Terminal safer.
